# 中国传统色 · 产品战略文档

> 战略锚点：把"中国传统色"从一个好看的色卡库，变成创作者真正用得起来的工具——而每一次使用，都在强化它作为文化 IP 的调性。工具价值带来留存，文化叙事带来传播，两者互为飞轮。

---

## 1. 一句话定位（README Slogan 候选）

**「742 种中国传统色——有名有姓，过 WCAG，直接落版。」**

副标（承文化 IP）：*每一个颜色，都跟着你的代码、你的版面一起被看见。*

**为什么是这句，不是别的：** 竞品格局是一个清晰的三象限，本项目独占一块无人区——

| | 有色名（文化） | 无色名（纯算法） |
|---|---|---|
| **能落版（工具）** | **← 本项目独占** | Coolors / Adobe Color |
| **不能落版** | 各类中国色站 / 帝国理工中国色 | — |

竞品要么"有名无用"（中国色站只能查 HEX，复制不进生产），要么"有用无名"（Coolors 配色强但色无名无姓）。本项目的 `theme-forge`（一个传统色名 → 整套过 WCAG 的 shadcn `globals.css`）和 `terminal`（7 种终端配置，每个生成色都保留传统色名注释）是**唯一把文化色名焊进可交付产物**的站。这是当下唯一已兑现、可现场演示、竞品给不出的硬壁垒，必须用它钉死定位。

**诚实校准（关乎 IP 信誉，不能塌）：** 另外两条"壁垒"目前只是叙事承诺，不能当已有的卖：
- **典籍出处考据（provenance）**：全仓 grep 不到任何典籍/朝代/染料数据，是最弱的一条，只能作为路线图讲。
- **失败根因诊断（10 个 skill）**：是写给 LLM 的自然语言协议，仓库内零可执行脚本，对比度全靠模型现算、不可复现。

**核心洞察：四类用户的留存链路其实已铺到约 80%**——skills 把设计动作显性化、`theme-forge`/`terminal` 把文化色焊进产物、`daily-playground` 已做好三版式三文案。但他们**全部断在同一个物理终点：东西做出来了，却"带不走、发不出、装不上"**。这正是上面三个杠杆。补它们比加任何新工具都更撬飞轮，因为每一次出图/装载，都顺带把传统色名带向社媒和别人的代码库——这正是锚点说的"每次使用都强化文化 IP"。

## 3. 产品创意（核心）

评判标准：存活分高 + 撬动飞轮 + 契合纯静态零依赖架构。每条都给出"做什么 / 飞轮角色 / 工作量 / 最强反对 + 应对"。

### 🟢 先做（30 天内动手，解锁飞轮的三个杠杆）

#### A. 「传统色身份证」一键出图 —— 激活 daily-color-playground
- **做什么：** 给 `daily-color-playground` 补手写 Canvas2D 的 PNG 导出（契合零依赖调性，拒绝 html2canvas）。同时三步接通飞轮：① 换用共享 `images.js`/`harmonies.js` 真数据，弃用 166 处硬编码；② 进 `shared-chrome` 导航 + 进 sitemap；③ 接 `favorites`。卡片底固定印 `colors.xiaoxiaodong.ai` 水印（可点 UTM）。
- **用户价值：** 内容创作者点一下就拿到带色名/拼音/CMYK/用法的小红书竖版/方形/公众号横版成品图。
- **飞轮角色：** 传播（总开关）。 **工作量：** M。
- **最强反对：** "把已渲染的 HTML/CSS 卡片绘到 Canvas"是被低估的陷阱——Canvas2D 无法绘制 DOM，要手写一套和 CSS 持续漂移的平行排版引擎；更致命的是字体：依赖本机 PingFang/YaHei，Windows/Linux 出豆腐块，"文化 IP 成品图"在别人机器上字体崩坏直接违背锚点。
- **应对（重要，改形态）：** **不要"重画 DOM 卡片"，改用 SVG 单源渲染**——与现成的 742 张 `colors/cards/*.svg` 管线同构，矢量可控、零漂移；导出时序列化 SVG 交浏览器渲染成 PNG，或直接给 SVG 下载（设计师更爱矢量）。中文用**子集化打包的 Noto Serif SC woff2**（只含库内色名汉字），`await document.fonts.ready` 后再绘，杜绝字体漂移。先把"一张字体绝对正确、自带回链"的卡跑通跑漂亮。

#### B. skills「装得起来」+「带色去问」复制按钮
- **做什么：** ① 在 `skills.html` 顶部和三语 README 加一段 Claude Code 安装说明（`SKILL.md` 本就是 Claude 原生格式，`cp 到 ~/.claude/skills` 即可）；② 在 `generator`/`palettes`/`theme-forge` 加"复制提示词"按钮，把当前选中色拼成纯文本（"我选了这些传统色 [色名+HEX]，请用 /xxd-ui-token 帮我生成 token"）。
- **用户价值：** 设计师/开发者从"在网页看得到"变成"装进日常 AI 工作流每周用"。
- **飞轮角色：** 留存。 **工作量：** S。
- **最强反对：** "补 Cursor 清单"是伪命题——Cursor 无 skill 安装机制；"直通 default_prompt"做不到——它是宿主里写死的静态字符串，浏览器无法动态改写已安装 agent。
- **应对：** 不碰 Cursor、不假装第二份清单；"直通"降级为朴素的"复制提示词文本供粘贴"，纯 client-side。上线后用 Plausible 看点击率（站内行为目前零采集，正好补一个可量化信号），有数据再考虑结构化护照。

#### C. 偿还稳定主键结构债（阻塞后续一切考据/导出）
- **做什么：** 当前色卡 id 靠目录中文排序动态生成、HEX 靠"文件名色名 == master-list 色名"字符串精确匹配，匹配不上**静默 hex=null 无告警**——改名/重排即错位。把 `master-list` 升级为结构化表（`stableId, 色名, HEX, pinyin`），并在 `build-manifest` 把 join 失败从静默改为**构建失败**（复用现有 `verify-*.mjs` 习惯加 `verify-manifest-join`）。同步把 `master-list` 第 5 行的作者本机绝对路径 `/Users/admin/Desktop/...` 换成仓库内相对说明。
- **用户价值：** 间接——所有后续考据/分享/导出建在稳定地基上。
- **飞轮角色：** 基建。 **工作量：** S–M。
- **最强反对：** 不直接产生用户价值，作者可能想跳过。
- **应对：** 这是流沙问题——不先做，B 站获客主引擎里印的出处、SEO 色页里织的典故都会随文件改名静默错位，反而砸 IP 信誉。独立成 PR，价值确定，必须先做。

### 🟡 紧跟（90 天，把工具价值做厚 + 把最弱壁垒补成最强）

#### D. 配色「体检卡」——把不可复现的对比度变成可甩客户的产物
- **做什么：** 设计师粘贴现有 HEX/CSS 变量，用 `color-core.js` 现成的 WCAG `contrast/relLum` 真算出每对配色对比比值、pass/fail，并从 742 库按 Lab 距离给出最近合规替换色（**替换色卡上印传统色名**，修可读性也传播色名）。分享靠 `?audit=` 把配色编码进链接（自描述链接，诚实告知非作者掌控的稳定页）；不可篡改的快照走"导出一张 PNG/SVG 体检卡"。
- **用户价值：** 把 LLM"现算、不可复现"的对比度变成确定性、可回访、可甩同事/客户的证据物。
- **飞轮角色：** 转化。 **工作量：** M 偏 L。
- **最强反对：** 原创意说"走 build-color-pages 同模式出稳定报告页"是误读——该管线是构建期生成、产物 commit 进 git，只能为已知的 742 色出稳定 URL，无法为用户此刻粘贴的任意 HEX 出作者掌控的链接；且"从 742 找最近合规色"的代码只活在构建脚本里，浏览器没加载，是净新增。
- **应对：** 诚实定位为"客户端配色体检"，分享 = 自描述链接 + 可下载体检卡（顺手补全 PNG/SVG 导出）。"742 最近合规替换"当真正的差异化单独立项（Lab + contrast 联立选色），别假装现成。输入口优先吃 `theme-forge` 导出的 css / `generator` 的 `?colors=` / 收藏色板，让审计成为既有工作流下游。

#### E. 文化考据数据层（小而真、带置信度的策展层）
- **做什么：** 新建 `docs/chinese-color-provenance.json`（挂 stableId），在 `build-manifest` 的 `payload.map` 多 spread 一个 `...provenance`，下游 742 SEO 色页 / use-cases 模板 / 分享卡自动织入"朱砂出自《天工开物》"这类典故。
- **用户价值：** 四类用户共同的"文化弹药"，把"742 内容站"升级成"中国传统色百科"——别人无法低成本复制的内容护城河。
- **飞轮角色：** 叙事。 **工作量：** L（内容工程，非工程任务）。
- **最强反对（最关键）：** 742 色里大量不可考——柏林蓝/尼罗蓝是外来译名、芒果黄/品红是现代营销名、墨绿/深绿是后期扩充色。批量 LLM 生成会捏造典籍卷次，而一旦把"考据"焊进已被收录的 SEO 页和对客户的分享卡，**错误考据就成了可被截图打脸的硬伤，直接摧毁而非强化文化 IP 信誉**。`daily-playground` 的 UI hint 已自陈"意象为示例文案，正式版接出处考据"——作者自己都承认手上没真考据源。
- **应对：** **降维成"小而真、可标注置信度的策展层"**：① provenance 字段必带 `source` 引用 + `confidence`（verified/folk-etymology/none）；② 前端只在 `confidence=verified` 时印出处，无考据的色诚实留白或只显示"民间色名"——**把"诚实"做成 IP 调性**；③ 不批量生成，先人工策展 30–50 个有确凿出处的矿物/染料色（朱砂/石青/群青/靛蓝），CONTRIBUTING 加考据贡献指南做社区共建。用真东西打样飞轮，不用注水内容透支信任。

#### F. 交付物导出扩面（聚焦经得起推敲的格式）
- **做什么：** 在 `terminal-serialize.js` 的 `FORMATS` 表 / `theme-forge` 的集中式 switch 加分支：`globals.css`(v4 @theme) + `tailwind.config`(明确 v3) + `tokens.json`（**严格对齐 Tokens Studio W3C DTCG schema** `$value/$type`）三个可单独下载，每个保留色名注释。把 CMYK 落进数据层（把 `app.js`/`dictionary.js` 重复的 `cmykFromRgb` 抽成共享 util，构建期算入），兑现 README"每张色卡含 CMYK"的承诺。
- **用户价值：** 设计师/前端产出能直接进 Figma 与代码库。
- **飞轮角色：** 转化。 **工作量：** M。
- **最强反对：** ASE 是 Adobe Swatch 二进制大端格式（Lab/RGB 浮点 + UTF-16 色名），不是"加 switch 拼字符串"，解析失败会毁信任；拍脑袋的 `tokens.json` Figma 大概率不识别，又是"说到没做到"。
- **应对：** 砍掉打包野心，只做经得起推敲的三件文本格式 + 单测；ASE 单独立项并标"实验性"或直接砍。修正 README 文案-数据落差。

### 🔵 储备（半年后，工具价值被验证后再投入）

- **G. 系列识别色生成器（留存）：** 博主选锚色，按 harmony 排未来 N 期变量色 + 批量导出 ZIP。**应对反对：** 不承诺"订阅推送"（静态站做不到），承诺"一次设定、可书签 URL 序列 + 全年成图一次打包带走"。**前置依赖 A 的导出能力。**
- **H. 收藏升级为"我的传统色工作台"（留存）：** 给 `favorites-store.js` 加 export/import JSON，先把 `explorer`/`dictionary`/`gradients`/`theme-forge`/`terminal` 全接入写收藏（数据契约需先归一）。**应对反对：** 砍掉"多项目/版本化/对比"重账务，只做"带得走" + 一条最高价值回灌通路（收藏色一键作锚色送进 theme-forge/terminal，加 `?anchor=NNN` URL 入口）。
- **I. 图表配色器（转化）：** 把 `xxd-data-viz` 做成 ECharts/Chart.js option 生成器。**应对反对：** 传统色库暖色为主、撑不起 6–12 系列 categorical，**收窄到 highlight + dashboard 语义色**（朱砂=danger、松绿=success，把文化语义焊进 token），categorical 老实标注"≤5 系列"。
- **J. 最薄 BaaS（仅留存被验证后）：** 跨端收藏同步 + 站内行为分析。**先用纯前端收藏 import/export 缓解**，云同步用 Cloudflare Workers KV/D1 做最薄一层，保持零运维调性。**不要过早建后端。**

## 4. 用户与市场

### 四类精确画像 + JTBD + 为什么会主动传播

| 画像 | JTBD | 主动传播的理由 | 当前断点 |
|---|---|---|---|
| **A. 接私活的中小/自由设计师**（高频留存核心） | 收到模糊 brief，30 分钟内拿出能落版、过甲方、面积比清晰的中国色配色 | 把过 WCAG 的 token 交付给甲方/同事，附带文化故事增加专业感 | skills 装不上；产出止于 Markdown，接不进 Figma/ASE |
| **B. 小红书/公众号文化内容创作者**（最大传播人群，几乎未激活） | 每天产出一张有文化感、能涨粉、不用自己排版的色彩图文卡 | 成品图自带色名+出处+水印，转的是专业内容不是壁纸 | `daily-playground` 是孤儿；**全站零 PNG 导出** |
| **C. 做主题/设计系统的前端/独立开发者**（差异化最强，最易口碑） | 给 side project 一套有调性、不撞色、每色"有名有姓"的主题 | `globals.css`/`ghostty.conf` 里焊着传统色名，晒配置即晒文化 | 定位仍是"色卡库"，开发者搜不到；skills 零安装文档 |
| **D. 独立品牌主理人**（低频高价值，最易自发安利） | 撑得起整个品牌、多渠道不漂移、能写进 VI、印刷不翻车的中国色体系 | 把"色的文化故事"写进品牌叙事 = 免费内容弹药 | CMYK 数据层为空；零考据数据 |

### 渠道优先级（四档）

- **P0 — 小红书（获客+传播主战场）：** 承接"每日一色身份证"+"设计师速查卡"。**前置依赖 PNG 导出，故 PNG 是 P0 的 P0。** 在补齐导出前别投运营，否则"渠道选对了没东西可发"。
- **P1 — SEO（长尾免费获客底座）：** 742 色页已收录、JSON-LD 齐全。补文化考据内容 + 把 `daily-playground` 加进 sitemap（目前漏收=自废入口）+ 做站点 i18n 承接英日流量（当前断层：英日 README 引流进来落地全中文）。
- **P2 — GitHub（开发者获客+信誉+skill 分发）：** `theme-forge`/`terminal`/10 个 skill 是开发者最强钩子，应把 Studio Skills 从首屏后部前置为核心卖点 + 补一键安装文档。
- **P3 — X / B 站（品牌叙事+作者真人 IP）：** X 承文化叙事与作者真人感；B 站做"可解释配色"方法论长视频（skill 是天然脚本）。

## 5. 技术建设序列（基于纯静态架构现实，按依赖排）

架构根本特征：**派生字段极易、服务端状态极难**。真相源是一份 12KB 纯文本 master-list，任何挂在确定性构建管线上的能力（考据、CMYK、pinyin、新导出格式、SEO 聚合页、Canvas/SVG 分享卡）都是搬运级低成本；任何需要服务端持久化的能力（跨端收藏、账号、订阅、UGC、行为分析）都与零后端正面冲突。因此正确顺序是**先在纯前端把工具价值与传播物做厚，把后端推迟到留存被验证之后再以最薄 BaaS 引入**。

## 7. 关键指标与风险

### 飞轮转速量化

- **留存（工具价值）：** 周回访率；skills 安装数（GitHub clone/复制按钮点击）；导出动作数/访问（PNG/SVG/css/tokens.json 各分类计数——当前除 PV 外零采集，**补这个采集本身是第一优先的可量化基建**）。
- **传播系数（K）：** 带水印 UTM 回链的成品图引入的新访客 / 产出图数量。目标先让 K 可被观测，再谈优化。
- **获客：** 742 SEO 色页自然流量；小红书带回链笔记的导流；GitHub star 增速（**结果不是手段，只观测不优化**）。

### 最大的 3 个风险

1. **把"叙事承诺"当"已有"卖，反噬文化 IP 信誉。** provenance（典籍考据）和 failure-diagnosis（执行层）目前都无数据/无脚本。若对外宣称"有典籍出处考据"，被文化爱好者或专业媒体核查会反噬——这恰是最不能塌的资产。**对冲：** 只硬主张已兑现的 WCAG + "色名焊进产物"两条；考据用置信度字段 + 诚实留白，把诚实做成 IP 调性。

2. **传播物缺位却押注小红书 = 渠道空转。** 小红书是图驱动平台，全仓零位图导出。**对冲：** PNG/SVG 导出是 P0 的 P0，补齐前不投运营。

3. **过早建后端，把可无限免费扩量的静态站拖入有运维成本的服务端形态。** 跨端同步/账号/订阅看似刚需，与零运维冲突最大。**对冲：** 先用纯前端收藏 import/export 缓解，验证留存后再引最薄 BaaS。

*（次级风险：无 CI + 742 产物全入库 → 社区贡献会让 SEO 产物悄悄过期，扩 provenance/i18n 前必须补 CI；传播信誉单点押在个人 X 账号 @xiaoxiaodong01；skills 层 20M 冗余使任何数据更新成本×10。）*

## 8. 被否决 / 大幅重塑的想法（避免重复踩坑）

没有完全杀死的想法，但以下原始构想的**关键承诺在现架构下不成立，必须按上文重塑后才能做**，记录原因：

- **❌ "带稳定 URL 的体检报告页（走 build-color-pages 同模式）"** —— 该管线是构建期生成、产物入 git，只能为已知 742 色出稳定 URL，无法为用户任意 HEX 出作者掌控的链接。全站零后端。→ 改为自描述 `?audit=` 链接 + 可下载体检卡（创意 D）。

- **❌ "把已渲染的 HTML/CSS 卡片绘到 Canvas2D"** —— Canvas 无法绘制 DOM，要手写持续漂移的平行排版引擎；本机字体导致 PNG 在 Windows/Linux 崩坏。→ 改为 SVG 单源渲染 + 子集化 woff2（创意 A）。

- **❌ "全量 742 条典籍考据管线（一行 spread 即可）"** —— 工程是琐事，真难点是 742 条可验证内容从哪来；大量色不可考（外来译名/营销名/扩充色），批量 LLM 生成会捏造典籍、成为可被打脸的硬伤。→ 降维为小而真、带置信度的人工策展层（创意 E）。

- **❌ "给用户任意 HEX 用 Lab 最近距离贴传统色名（配色诊断分享卡）"** —— 会把 Material 蓝硬贴成"月白"（ΔE 10+），把严肃考据降格成"换皮命名器"，反噬唯一护城河。→ 改为"配色体检"：如实保留原 HEX，旁标最近传统色 + ΔE 距离 + 置信度（并入创意 D）。

- **❌ "邮件订阅分发（号称零后端）"** —— 邮件物理上不可能零后端（需表单后端+ESP+退订合规），与项目灵魂冲突；RSS 服务的受众与目标人群几乎不重叠；iframe 在微信/小红书/知乎会被 strip。→ 翻转为"成品产出口"（创意 A），RSS 仅作 daily JSON 的零成本副产品保留，不作主线。

- **❌ "ASE 当作加一个 switch 分支"** —— 二进制大端格式，解析失败毁信任。→ 单独立项标实验性或砍（创意 F）。

- **❌ "图表配色器撑 6–12 系列 categorical"** —— 传统色库暖色为主、冷/高彩度稀疏，凑不出感知可区分又像传统色的多系列。→ 收窄到 highlight + dashboard 语义色（创意 I）。
